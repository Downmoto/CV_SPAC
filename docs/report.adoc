== Abstract

This report presents the design, implementation, and evaluation of *Smart Parking Access Control (SPAC)*, an end-to-end computer vision system that automates vehicle authorization at parking facilities.
The system integrates YOLOv8 object detection for license plate localization, a dual-backend OCR engine with ten preprocessing variants for robust text extraction, and a fuzzy-matching module for resident database lookup.
Evaluated on 44 test images from the Kaggle Car Plate Detection dataset, the system achieves a 97.7% plate detection rate, 88.6% decision accuracy, and 85.7% recall for authorized residents.
The modular pipeline is fully configurable via a centralized YAML configuration and accessible through a unified command-line interface supporting all workflow stages from data preparation through evaluation.

== Introduction

=== Problem Statement

Parking access control remains a labor-intensive process at many residential and commercial facilities.
Traditional approaches rely on physical access cards, keypads, or manned security checkpoints — all of which incur ongoing operational costs, introduce human error, and inconvenience authorized residents.
An automated vision-based system that can identify vehicles by their license plates and grant or deny access in real time offers a compelling alternative.

=== Motivation

Automatic License Plate Recognition (ALPR) has matured significantly in recent years, driven by advances in deep learning-based object detection and optical character recognition.
However, assembling a reliable, end-to-end ALPR pipeline for access control requires careful integration of multiple components — detection, OCR, text normalization, and database matching — each with their own failure modes.
This project explores how these components can be composed into a practical, configurable system with measurable performance.

=== Objectives

The primary objectives of this project are:

. *Detection:* Train a lightweight object detector to reliably localize license plates in images.
. *Recognition:* Extract plate text using multi-backend OCR with robust preprocessing.
. *Matching:* Match extracted text against an authorized resident database using exact and fuzzy matching.
. *Decision:* Produce access grant/deny decisions with confidence scores.
. *Evaluation:* Quantify system performance against ground-truth labels.
. *Tooling:* Provide a reproducible, configurable pipeline accessible via a single CLI.

== Background & Related Work

=== Automatic License Plate Recognition

Automatic License Plate Recognition (ALPR) systems have been widely studied in the computer vision literature.
A typical ALPR pipeline consists of three stages: plate detection (localization), character segmentation, and character recognition.
Modern deep learning approaches often collapse segmentation and recognition into a single OCR step, simplifying the pipeline to detection followed by end-to-end text recognition.

=== Object Detection with YOLO

The YOLO (You Only Look Once) family of detectors <<redmon2016>> has become a standard choice for real-time object detection tasks.
YOLOv8 <<jocher2023>>, developed by Ultralytics, provides a range of model sizes from nano (YOLOv8n, 3.2M parameters) to extra-large.
The nano variant offers favorable speed-accuracy tradeoffs for edge deployment, making it suitable for real-time plate detection where inference latency matters.

=== Optical Character Recognition

Modern OCR engines such as EasyOCR <<jaided2020>> and PaddleOCR <<du2020>> leverage deep neural networks for text detection and recognition.
EasyOCR uses a CRAFT-based text detector with a sequence-to-sequence recognizer, while PaddleOCR employs a PP-OCR pipeline with lightweight models.
Both support multiple languages and are available as open-source Python libraries.

The quality of OCR results is highly sensitive to image preprocessing.
Common techniques include grayscale conversion, histogram equalization (CLAHE), binarization (Otsu's method, adaptive thresholding), denoising, and geometric rectification — all of which are employed in this system.

=== String Matching for Plate Verification

Exact string matching is insufficient for plate verification due to OCR character confusions (e.g., `0` ↔ `O`, `1` ↔ `I`, `8` ↔ `B`).
Fuzzy string matching algorithms such as the Levenshtein distance and its normalized variants provide a similarity score that can tolerate minor character errors.
RapidFuzz <<maxbachmann2021>> is a high-performance Python library implementing these algorithms, suitable for real-time matching.

=== Pipeline Stages

[arabic]
. **Plate Detection** — A YOLOv8n model localizes the license plate region within the input image, returning a bounding box and confidence score.
. **Plate Cropping** — The detected region is extracted with configurable padding (14% horizontal, 22% vertical) to preserve plate context while excluding background noise.
. **OCR Text Extraction** — A dual-backend OCR engine processes the cropped plate through ten or more preprocessing variants, scoring candidates by OCR confidence and a plausibility heuristic.
. **Resident Matching** — The extracted text is normalized and compared against a resident database using exact matching followed by fuzzy matching (90% similarity threshold).

Each stage produces structured output (bounding box, text, match result), which is aggregated into a per-image result record and serialized to JSON for downstream evaluation.

== Methodology

=== Dataset & Preparation

==== Source Data

The system uses the *Kaggle Car Plate Detection* dataset (`andrewmvd/car-plate-detection`) consisting of 433 annotated vehicle images with license plate bounding boxes in Pascal VOC XML format.

==== Data Conversion

The preparation module (`src.data.prepare_kaggle_car_plate_dataset`) performs:

. *XML Parsing:* Extracts bounding box coordinates (`xmin`, `ymin`, `xmax`, `ymax`) from VOC-format annotations.
. *YOLO Format Conversion:* Converts absolute pixel coordinates to YOLO center-normalized format: `(x_center, y_center, width, height)` relative to image dimensions.
. *Train/Val/Test Split:* Stratified random split with ratios 80/10/10 (seed 42), producing 346 training, 43 validation, and 44 test images.
. *Dataset YAML:* Generates an Ultralytics-compatible `dataset.yaml` specifying paths and class names.

==== Resident Database

A synthetic resident database (`data/db/residents.csv`) is seeded from ground-truth plate values and OCR predictions.
The database contains 36 entries with fields: `plate_number`, `resident_name`, `unit`, `vehicle_color`, and `status` (`active` or `inactive`).
The `active_ratio` of 0.85 produces approximately 31 active and 5 inactive records, simulating a realistic access control scenario.

=== Plate Detection

==== Model Selection

YOLOv8n (nano) was selected as the detection backbone for its balance of speed and accuracy.
With 3.2 million parameters and a model size of approximately 6 MB, it is suitable for deployment on resource-constrained hardware.

==== Training Configuration

.Detector Training Hyperparameters
[cols="1,1", options="header"]
|===
| Parameter | Value

| Base Model | `yolov8n.pt` (COCO pretrained)
| Epochs | 80
| Image Size | 640 × 640
| Batch Size | 16
| Device | GPU (CUDA device 0)
| Optimizer | SGD (Ultralytics default)
|===

The model was fine-tuned on the prepared dataset with a single class (`plate`).
Training artifacts — including weights, loss curves, and per-epoch metrics — are saved to `runs/detect/outputs/detector_train/`.

==== Inference Configuration

At inference time, the detector runs with a confidence threshold of 0.25.
The highest-confidence detection per image is selected, and the corresponding bounding box is passed to the cropping stage.
If no detection exceeds the threshold, the image is marked as "no detection" and the pipeline skips OCR and matching for that sample.

=== OCR Engine

The OCR engine is the most sophisticated component of the pipeline, designed to maximize text extraction quality under varying image conditions.

==== Dual-Backend Architecture

Two OCR backends are employed in parallel:

* *EasyOCR:* CRAFT-based text detector with a CTC/attention-based recognizer. Robust for high-contrast plates.
* *PaddleOCR:* PP-OCR v4 pipeline with lightweight recognition models. Complementary performance profile to EasyOCR.

For each preprocessing variant, both backends are queried.
This produces a large candidate pool from which the best result is selected.

==== Preprocessing Variants

Rather than committing to a single preprocessing pipeline, the OCR engine generates ten or more variants of each cropped plate image:

.OCR Preprocessing Variants
[cols="1,3", options="header"]
|===
| Variant | Description

| Original
| Unmodified cropped plate

| Upscaled (2×, 3×)
| Bicubic magnification for small plates

| Rectified
| Geometric rotation correction via contour-based angle estimation

| Flattened
| Perspective distortion correction via quadrilateral warp

| Grayscale
| Single-channel conversion

| Denoised
| Bilateral filtering to reduce noise while preserving edges

| CLAHE
| Contrast-Limited Adaptive Histogram Equalization for uneven lighting

| Otsu Binarization
| Global threshold binarization for high-contrast separation

| Adaptive Threshold
| Gaussian local thresholding for varying illumination

| Sharpened
| Kernel-based edge enhancement

| Full Pipeline
| All preprocessing steps applied sequentially
|===

==== Plausibility Scoring

Raw OCR output often includes noise, partial reads, or hallucinated text.
A plausibility scoring heuristic ranks candidates before confidence:

* *Length penalty:* Plates with ≤ 2 characters receive a −0.50 penalty (likely garbage).
* *Mixed alphanumeric bonus:* Plates containing both letters and digits are rewarded (characteristic of real plates).
* *Repetition penalty:* High character repetition with low character diversity is penalized.
* *Length reward:* Plates in the 5–10 character range receive a bonus.

The final ranking sorts by `(plausibility_score + OCR_confidence, OCR_confidence, text_length)` and selects the top candidate, provided it exceeds the minimum confidence threshold of 0.35.

=== Resident Matching

==== Text Normalization

Before matching, plate text is normalized:

* Converted to uppercase
* Non-alphanumeric characters removed
* Whitespace stripped

This ensures consistent comparison regardless of OCR formatting artifacts.

==== Matching Strategy

The matcher employs a two-tier approach:

. *Exact Match:* The normalized plate is looked up directly in a precomputed dictionary of normalized resident plates. If found, the match score is 100%.
. *Fuzzy Match:* If exact matching fails and fuzzy matching is enabled, RapidFuzz computes the normalized Levenshtein similarity between the input plate and every resident plate. The best match is returned if its score meets or exceeds the threshold (default: 90%).

== Evaluation

=== Evaluation Methodology

The evaluation module computes metrics at two levels:

==== Base Metrics (No Ground Truth Required)

* *Detection rate:* Fraction of images where the detector found a plate.
* *OCR success rate:* Fraction of detected plates that produced non-empty text.
* *Decision distribution:* Count of granted vs. denied decisions.
* *Mean confidences:* Average detector and OCR confidence scores.

==== Ground-Truth Metrics (Labeled Data Required)

With a manually annotated ground-truth CSV specifying expected decisions and plate text per image:

* *Decision metrics:* Accuracy, Precision, Recall, F1-Score computed by treating "Access Granted" as the positive class.
* *Confusion matrix:* True Positives, True Negatives, False Positives, False Negatives.
* *Plate exact-match rate:* Fraction of plates where OCR output exactly matches the ground-truth plate text (excluding samples labeled "UNKNOWN").

=== Analysis & Discussion

==== Strengths

*High Detection Reliability.* The YOLOv8n detector achieves a 97.73% detection rate, failing on only 1 of 44 test images.
This demonstrates that even the nano-sized model, when fine-tuned on domain-specific data, provides robust plate localization.

*Strong Recall.* The system correctly identifies 6 of 7 authorized residents (85.71% recall), meaning it rarely denies access to legitimate residents.
In an access control scenario, high recall is critical for user satisfaction.

*Effective Fuzzy Matching.* Despite a low plate exact-match rate (30.77%), fuzzy matching at the 90% threshold compensates for OCR character errors.
The gap between plate exact-match (30.8%) and decision accuracy (88.6%) illustrates the value of the fuzzy matching layer.

==== Weaknesses

*Low Precision (60%).* Of 10 images predicted as "Access Granted," 4 are false positives — unauthorized vehicles granted access.
In a security context, this is the most concerning metric.
Root causes include:

* Fuzzy matching accepting plates with coincidental similarity to a resident entry
* OCR character confusions (e.g., `0` ↔ `O`, `1` ↔ `I`) producing text that closely resembles a different resident's plate

*Low Plate Exact-Match Rate (30.8%).* Only 12 of 39 labeled plates were read with perfect character accuracy.
Contributing factors include:

* Variable image quality and lighting conditions
* Plate designs with decorative fonts or non-standard layouts
* Small plate regions requiring aggressive upscaling
* Perspective distortions not fully corrected by rectification

*Moderate OCR Confidence (0.593 mean).* The average OCR confidence is below 0.60, indicating the engine operates near its reliability boundary on this dataset.
Confidence-based filtering mitigates but does not eliminate unreliable reads.

==== False Positive Analysis

The 4 false positives are the primary area for improvement.
Potential mitigations include:

* Raising the fuzzy match threshold (e.g., from 90% to 95%)
* Requiring a minimum OCR confidence for access decisions
* Implementing a confirmation mechanism (e.g., second image capture)
* Adding temporal consistency (same plate recognized across multiple frames)

== Limitations & Future Work

=== Current Limitations

. *Small Test Set:* Evaluation on 44 images provides indicative but not statistically conclusive results. A larger, more diverse dataset would strengthen confidence in the reported metrics.

. *Single Frame Decisions:* Each image is processed independently. Real-world deployments would benefit from temporal smoothing across multiple frames of the same vehicle.

. *Synthetic Resident Database:* The resident database is auto-generated from ground-truth and OCR predictions rather than representing a genuine facility database.

. *Static Thresholds:* Confidence and fuzzy matching thresholds are fixed globally. Adaptive thresholds based on image quality could improve performance.

. *No Plate Segmentation:* The system detects the plate region but does not segment individual characters. Character-level recognition could improve accuracy for plates with uncommon layouts.

=== Future Work

. *Threshold Optimization:* Systematic sweep of detector, OCR, and fuzzy matching thresholds to find the Pareto-optimal operating point for the precision–recall tradeoff.

. *Data Augmentation:* Augmenting training data with synthetic distortions (blur, noise, perspective) to improve detector and OCR robustness.

. *Multi-Frame Fusion:* Aggregating detections across video frames using temporal voting or plate-tracking to reduce single-frame errors.

. *Specialized OCR Models:* Fine-tuning a recognition model specifically on license plates (e.g., using STR benchmarks) rather than relying on general-purpose OCR.

. *Edge Deployment:* Profiling and optimizing the pipeline for embedded hardware (Jetson Nano, Raspberry Pi) using TensorRT or ONNX Runtime.

. *Expanded Evaluation:* Testing on diverse plate standards (European, Asian formats) and under controlled degradation conditions (rain, low light, motion blur).

== Conclusion

This project demonstrates a practical, modular approach to automated parking access control using license plate recognition.
The SPAC system integrates YOLOv8 detection, dual-backend OCR with extensive preprocessing, and fuzzy string matching into a configurable pipeline that achieves 88.6% decision accuracy and 85.7% recall on its test set.

The modular architecture — with each pipeline stage independently replaceable — supports iterative improvement and experimentation.
The centralized YAML configuration and unified CLI eliminate manual configuration and enable reproducible workflows.

Key findings include the critical role of fuzzy matching in bridging the gap between imperfect OCR output (30.8% exact match) and practical access decisions (88.6% accuracy), as well as the importance of multi-variant preprocessing for maximizing OCR robustness under diverse image conditions.

The primary area for improvement is precision (60%), where false positive access grants pose security risks.
Future work should focus on threshold optimization, multi-frame fusion, and specialized OCR models to close this gap.
